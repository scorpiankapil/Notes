- Web applications

- Embedded Systems

- It is an object oriented programming language
- Java is platform independent language
- Java is fairly simple and secure
- Java has large standard library

# Java Architecture

Java Architecture explains **how a Java program is compiled and executed** from source code to output.

- You write your Java program in a file ending with **`.java`**. (This is human-readable code.)
    - Example: `Hello.java`
- The **Java Compiler (`javac`)** checks your code and converts it into a Bytecode (**`.class file`**) .
    - Example: `Hello.class`
- The `.class` file contains **Bytecode**.
    - Bytecode is a special language that any JVM can understand.
- The **JVM (Java Virtual Machine)** reads this Bytecode.
- Then JVM takes Bytecode from .class file and interprets into **Machine code 0/1** (the language understood by the computer's CPU)
- The CPU executes the Machine Code and shows the **output** on your screen.

```
Java Code (.java)
        ↓
      javac
        ↓
Bytecode (.class)
        ↓
       JVM
        ↓
 Machine Code
        ↓
      Output
```

## **JVM (Java Virtual Machine)**

JVM (Java Virtual Machine) is an engine that takes the `.class` file (Bytecode), converts it into Machine Code, and runs the program.
```

                JVM
                 |
    --------------------------------
    |              |              |
Class Loader   Memory Area   Execution Engine
                                   |
                     -------------------------
                     |           |           |
                Interpreter     JIT         GC
                              Compiler
```

### 1. Class Loader

The **Class Loader** is responsible for **loading the `.class` file into JVM memory**.

When you run:

```
java Hello
```

JVM first asks:

```
"Where is Hello.class?"
```

The Class Loader finds it and loads it into memory.

**Steps**
```
Hello.class      
|      
v
Class Loader      
|      
v
Memory
```


### 2. Memory Area (Runtime Data Area)

This is the memory used by JVM while the program is running.

Think of it as the JVM's workspace.

#### A. Method Area

Stores:

- Class information
- Method information
- Static variables

Example:

```
class Student
	{    
		static int count = 0;
	}
```

`count` is stored in the Method Area.

#### B. Heap Area

Stores:

- Objects
- Instance variables

Example:

```
Student s = new Student();
```

The object is stored in the Heap.

```
Heap 
| 
+-- Student Object
```

Most memory is consumed in the Heap.

#### C. Stack Area

Stores:

- Local variables
- Method calls

Example:

```
public static void main(String[] args){    int x = 10;}
```

`x` is stored in the Stack.

```
Stack | +-- x = 10
```

#### D. PC Register

Stores the address of the current instruction being executed.

Think of it as:

```
 "Which line of code am I executing right now?"
```

#### E. Native Method Stack

Used when Java calls code written in languages like C or C++.


### 3. Execution Engine

Once the Class Loader loads the class and memory is allocated, the Execution Engine runs the program.

#### Interpreter

The Interpreter reads Bytecode **line by line** and executes it.

```
Bytecode   
|   
v
Interpreter   
|
Reads one instruction
Executes it
Reads next instruction
Executes it
```

**Example**

Suppose Bytecode contains:

```
Instruction 1
Instruction 2
Instruction 3
```

Interpreter does:

```
Read 1 → Execute
Read 2 → Execute
Read 3 → Execute
```

#### JIT Compiler (Just-In-Time Compiler)

To solve the speed problem of the Interpreter.

JIT watches the program and finds code that runs frequently.

Example:

```
for(int i=0;i<100000;i++)
{    
	System.out.println(i);
}
```

The loop runs many times.

JIT says:

```
"Instead of translating this every time, I'll convert it directly into Machine Code."
```

```
Bytecode   
|   
v
JIT Compiler   
|
Machine Code
```

Now JVM executes Machine Code directly.

**Result**

```
Interpreter = Slower
JIT Compiler = Faster
```

JVM uses **both Interpreter and JIT**.

```
New code → Interpreter
Frequently used code → JIT Compiler
```

#### Garbage Collector (GC)

Garbage Collector automatically removes unused objects from Heap Memory.

```
Student s = new Student();
```

Object created:

```
Heap 
| +-- Student Object
```

Now:

```
s = null;
```

No variable points to the object anymore.

```
Heap 
| +-- Student Object (Unused)
```

GC detects:

```
"Nobody is using this object."
```

So it removes it.

```
Heap 
| 
Empty
```

### Why is GC Important?

Without GC:

```
Unused objects keep filling memory
Memory becomes full
Program crashes
```

GC automatically frees memory.

## **JRE (Java Runtime Development)**

JRE is a package that contains the JVM and Java libraries required to run Java programs.

It contains everything needed to execute a Java application, but **it does not contain the Java compiler (`javac`)**.

```
JRE
 |
 +-- JVM
 |
 +-- Java Libraries (API)
```

## **JDK (Java Development Kit)**

JDK is a collection of tools used to write, compile, debug, and run Java applications.

```
JDK
 |
 +-- JRE
 |     |
 |     +-- JVM
 |
 +-- Development Tools
       |
       +-- javac
       +-- java
       +-- javadoc
       +-- jar
```


# JVM vs JRE vs JDK

|JVM|JRE|JDK|
|---|---|---|
|Java Virtual Machine|Java Runtime Environment|Java Development Kit|
|Responsible for executing Java Bytecode|Provides an environment to run Java programs|Provides an environment to develop, compile, and run Java programs|
|Converts Bytecode into Machine Code|Contains JVM|Contains JRE|
|Cannot compile Java code|Cannot compile Java code|Can compile Java code using `javac`|
|Used for program execution|Used for running Java applications|Used for Java development|
|Smallest unit|Larger than JVM|Largest package|
