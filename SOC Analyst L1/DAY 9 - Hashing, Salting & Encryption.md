# Hashing

A **hash** is a fixed-length string of characters generated by applying a **hashing algorithm** to data (such as a password).

It acts like a **digital fingerprint** of the original data.

- A hash is the output of a one-way mathematical transformation that converts data of any size into a fixed-length value called a hash (or hash value).
- No matter how long input is -> output length is fixed

```
Input -> Hash Function -> Fixed Length Output
```

**Example:**

```
Input:
Hello123

Hash (SHA-256):
872e4e50ce9990d8b041330c47c9ddd11bec6b503ae9386a99da8584e9bb12c4
```

### Properties of Hashing

- One-way (cannot reverse easily)
- Deterministic (Same input -> same output)
- Fixed output length
- Small input change -> complete different output (This is called Avalanche Effect).

## Common Hash Algorithms

|Algorithm|Secure Today?|Notes|
|---|---|---|
|**MD5**|❌ No|Very weak and vulnerable to collisions. Not recommended.|
|**SHA-1**|❌ No|Broken and no longer considered secure.|
|**SHA-256**|✅ Yes|Strong hashing algorithm, widely used for integrity checks and digital signatures.|
|**SHA-512**|✅ Yes|Stronger version of SHA-2 with a larger hash size.|
|**bcrypt**|✅ Very Strong|Specifically designed for securely storing passwords.|
|**Argon2**|✅ Very Strong|Modern password hashing standard and currently one of the best choices for password storage.|

### Why Are Passwords Hashed?

Passwords are hashed to **protect user accounts**. Instead of storing the actual password, websites store its **hash**, so even if the database is stolen, the original passwords are not easily exposed.

- **Protects user passwords** if the database is stolen.
- **Original passwords are not stored** in the database.
- **Makes it difficult for attackers** to recover passwords.
- **Reduces the risk of credential theft.**
- **Helps prevent unauthorized access.**
- **Verifies passwords securely during login.**


# Salting 

Salting is the process of adding a **random, unique value (called a salt)** to a password **before hashing** it.

This makes the resulting hash unique, even if two users have the same password.

##### **Example With Salt** 

**User 1:**

```
Password : Hello123
Salt     : X7@9P
```

Combined:

```
Hello123X7@9P
      ↓
SHA-256
      ↓
a8c72e9d...
```

**User 2:**

```
Password : Hello123
Salt     : M5#2K
```

Combined:

```
Hello123M5#2K
      ↓
SHA-256
      ↓
f1d94ab8...
```

Database:

|User|Password|Salt|Hash|
|---|---|---|---|
|Kapil|Hello123|X7@9P|a8c72e9d...|
|Rahul|Hello123|M5#2K|f1d94ab8...|

Even though both users have the **same password**, their hashes are **different** because of different salts.

##### Why is Salting used?

- Prevents **Rainbow Table Attacks**.
- Makes password hashes unique.
- Protects users with the same password.
- Makes password cracking much more difficult.
- Improves password security.

# Hashing vs Encryption

|Hashing|Encryption|
|---|---|
|Converts data into a fixed-length hash value.|Converts data into ciphertext.|
|One-way process.|Two-way process.|
|Cannot be reversed.|Can be decrypted using a key.|
|Does not require a key.|Requires an encryption/decryption key.|
|Produces a fixed-length output.|Output size usually depends on the input size.|
|Used for password storage and data integrity.|Used for protecting confidential data.|
|Common algorithms: MD5, SHA-256, SHA-512, bcrypt, Argon2.|Common algorithms: AES, DES, 3DES, RSA, ECC.|
|Used to verify data integrity.|Used to maintain data confidentiality.|
|Example: Storing user passwords.|Example: HTTPS encrypting communication between a browser and a website.|

```
Password should NEVER be encrypted.
They should be hashed + salted
```

# SOC Perspective

When a **database is leaked or compromised**, a SOC analyst must determine how passwords were stored to understand the risk.

If database leaked, you must assess:
- Was hashing used?
- Was salting used?
- Which algorithm?
- Was it bcrypt or just MD5?

```
If Weak hashing + no salt = High risk of password compromise and credential stuffing attacks.
```


# Real SOC Scenario

##### Step 1: Company Stores Passwords

The company stores user passwords using **MD5 without salting**.

##### Step 2: Database is Breached

An attacker steals the user database containing password hashes.

##### Step 3: Attacker Cracks the Hashes

Because **MD5 is weak** and there is **no salt**, the attacker cracks many password hashes within minutes.

##### Step 4: Users Reuse the Same Password

Many users use the same password for:

- Email
- VPN
- Banking
- Social media

##### Step 5: Credential Stuffing Begins

The attacker uses the stolen username-password pairs to log in to other websites and services.

This is called a **Credential Stuffing Attack**.

## What Does the SOC See?

##### 1. Login Attempts from Multiple IP Addresses

The same account is accessed from many different IP addresses.

##### 2. Account Takeovers

Attackers successfully log in using the stolen credentials and take control of user accounts.

##### 3. Impossible Travel Alerts

The same user appears to log in from two geographically distant locations in an impossible amount of time.

**Example:**

```
10:00 AM → Login from India

10:10 AM → Login from Germany
```

Since traveling from India to Germany in **10 minutes** is impossible, the SOC generates an **Impossible Travel Alert**.

# Pepper

Pepper is an **additional secret value** that is added to a password **before hashing**, just like a salt. However, **unlike a salt, the pepper is not stored in the database**. It is kept in a secure location, such as the application server or a secrets manager.

- Adds an extra layer of security.
- Protects passwords if the database is stolen.
- Makes password cracking much more difficult.
- Prevents attackers from cracking hashes using only the stolen database.
- Works together with **salt** to strengthen password security.

##### Example

**Password**

```
Password: Hello123
```

**Pepper (Secret)**

```
Pepper: MySecretKey@2026
```

**Combined**

```
Hello123MySecretKey@2026
```

**Hash**

```
SHA-256
      ↓
872e4e50ce9990d8...
```

# Encryption 

Encryption is the process of converting **readable data (plaintext)** into **unreadable data (ciphertext)** using an encryption algorithm and a key. Only someone with the correct key can decrypt the ciphertext back into the original data. 

```
Plaintext
     │
     ▼
Encryption Algorithm + Key
     │
     ▼
Ciphertext
     │
     ▼
Decryption + Key
     │
     ▼
Plaintext
```


## Why Encryption is Used?

Encryption is used to **protect sensitive data** by ensuring that only authorized users with the correct key can read it.

- Protects sensitive and confidential information.
- Prevents unauthorized access to data.
- Secures data during transmission over the internet.
- Protects stored data on devices and servers.
- Maintains data confidentiality and privacy.
- Prevents attackers from reading stolen data.
- Helps organizations meet security and compliance requirements.
- Secures online banking, emails, and messaging applications.
- Protects financial and personal information.
- Ensures only authorized users can access the original data.

# Types of Encryption

## 1. Symmetric Encryption

Symmetric Encryption is a type of encryption in which the **same secret key** is used to **encrypt** the data and **decrypt** the data.

Both the sender and the receiver must know and use the **same key**.

- Encrypts data quickly.
- Protects sensitive information.
- Suitable for encrypting large amounts of data.
- Used for secure communication and data storage.

**Example:**
- Disk Encryption
- VPN Tunnels
- File Encryption

#### Popular Algorithms

| Algorithm                              | Definition                                                                                                                                                                                            |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AES (Advanced Encryption Standard)** | AES is a **symmetric encryption algorithm** that uses the same secret key for encryption and decryption. It is the **most widely used and secure** encryption standard for protecting sensitive data. |
| **DES (Data Encryption Standard)**     | DES is an older **symmetric encryption algorithm** that uses a **56-bit key**. It is now considered **insecure** because modern computers can crack it relatively quickly.                            |
| **3DES (Triple DES)**                  | 3DES is an improved version of DES that **applies the DES algorithm three times** to increase security. It is more secure than DES but slower and has largely been replaced by AES.                   |
| **Blowfish**                           | Blowfish is a **fast symmetric encryption algorithm** that supports variable key lengths (32–448 bits). It is secure but is less commonly used today than AES.                                        |
| **Twofish**                            | Twofish is a **symmetric encryption algorithm** designed as a successor to Blowfish. It is highly secure, supports key sizes up to **256 bits**, and is suitable for protecting sensitive data.       |

## 2. Asymmetric Encryption

Asymmetric Encryption is a type of encryption that uses **two different keys**:

- **Public Key** – Used to encrypt the data.
- **Private Key** – Used to decrypt the data.

The **public key** can be shared with anyone, but the **private key** must be kept secret.

- Securely exchanges encryption keys.
- Protects sensitive information.
- Provides authentication.
- Supports digital signatures.
- Ensures secure communication over the internet.

##### How Asymmetric Encryption Works

1. The receiver generates a **public key** and a **private key**.
2. The receiver shares the **public key** with the sender.
3. The sender encrypts the message using the **public key**.
4. The encrypted message is sent to the receiver.
5. The receiver decrypts the message using the **private key**.
6. The original message is recovered.

**Example:**

- HTTPS Websites
- SSL/TLS handshake
- Email encryption (PGP)

#### Common Asymmetric Cryptography Algorithms

|Algorithm|Definition|
|---|---|
|**RSA (Rivest-Shamir-Adleman)**|RSA is an **asymmetric encryption algorithm** that uses a **public key** for encryption and a **private key** for decryption. It is widely used for secure communication, digital signatures, and SSL/TLS certificates.|
|**ECC (Elliptic Curve Cryptography)**|ECC is an **asymmetric encryption algorithm** that provides the **same level of security as RSA using much smaller keys**, making it faster and more efficient. It is commonly used in mobile devices, IoT devices, and SSL/TLS.|
|**Diffie-Hellman (DH)**|Diffie-Hellman is a **key exchange algorithm**, not an encryption algorithm. It allows two parties to **securely exchange a shared secret key** over an insecure network, which is then used for symmetric encryption.|

# SOC Analyst Perspective

## Understanding Hashing and Encryption Helps In

##### 1. Investigating Data Breaches

- Determine whether stolen data was encrypted or hashed.
- Assess the impact of the breach.

##### 2. Analyzing Password Dumps

- Identify the hashing algorithm used (e.g., MD5, SHA-256, bcrypt).
- Determine how easily the passwords can be cracked.

##### 3. Understanding Credential Theft

- Investigate how attackers obtained user credentials.
- Determine whether credential stuffing or password cracking is likely.

##### 4. Investigating Encrypted Traffic

- Analyze encrypted network traffic (HTTPS, VPN, TLS).
- Verify whether communication is secure or suspicious.

##### 5. Malware Analysis

- Use file hashes to identify known malware.
- Verify file integrity by comparing hashes with threat intelligence databases.

## If Attackers Steal...

##### 1. Encrypted Database

- Data is encrypted.
- Attackers **cannot read the data** without the decryption key.
- The data is harder to access.

##### 2. Hashed Passwords

- Passwords are stored as hashes.
- Attackers **cannot directly read the passwords**.
- However, they **may attempt to crack the hashes offline** using brute force, dictionary attacks, or rainbow tables (especially if weak hashing algorithms like MD5 are used).
