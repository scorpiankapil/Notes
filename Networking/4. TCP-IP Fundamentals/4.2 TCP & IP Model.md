# TCP/IP Model

The TCP/IP Model is a networking model that explains how data is transmitted and communicated over networks and the internet using the TCP/IP protocol suite.

It divides network communication into different layers, where each layer performs a specific function.

It is similar to the OSI model but TCP/IP has 4 layers, instead of 7 layers in the OSI model.


## Layers of TCP/IP Model

|TCP/IP Layer|Main Function|Common Protocols|
|---|---|---|
|Application Layer|User services and network requests|HTTP, FTP, SMTP, NNTP|
|Transport Layer|Reliable/unreliable delivery|TCP, UDP|
|Internet Layer|Logical addressing and routing|IP, ARP, ICMP|
|Network Interface Layer|Physical network communication|Ethernet, Token Ring|

## Mapping of TCP/IP and OSI Model

|TCP/IP Model|OSI Model|
|---|---|
|Application Layer|Application + Presentation + Session|
|Transport Layer|Transport|
|Internet Layer|Network|
|Network Interface Layer|Data Link + Physical|

# Application Layer in TCP/IP Model

The Application Layer is the top layer of the TCP/IP model that allows users and applications to communicate over the network.

It is responsible for:

- Sending network requests
- Receiving network requests
- Providing network services to applications
- Allows communication between software and network

This layer is directly interacts with user applications or software such as Web browsers, Email applications and File transfer programs.


**Common Application Layer Protocols**

| Protocol | Purpose                 |
| -------- | ----------------------- |
| HTTP     | Transfers web pages     |
| SMTP     | Sends emails            |
| NNTP     | Transfers news articles |
| FTP      | Transfers files         |

## How It Works

1. A user uses an application like a web browser.
2. The application sends a network request.
3. The request travels through the network.
4. The receiving server accepts and processes the request.
5. The response is sent back to the user.

### HTTP

HTTP is a communication protocol used to transfer web pages and website data between a web browser and a web server.

HTTP is used for accessing and loading websites on the internet.

Port Number is 80

HTTP is stateless, meaning:
- Server does not remember previous requests automatically.

Each request is treated as:
- A new request

It allows:

- Users to send emails
- Mail servers to transfer emails between each other

# Transport Layer in TCP/IP Model

The Transport Layer is the 2nd layer that is responsible for end-to-end communication between applications running on different devices.

It handles both connectionless and connection-oriented communication

**Connection-oriented** is where a session is established before data transfer, and **connectionless communication**, where data is sent without establishing a session. When data comes from the Application Layer, the Transport Layer selects an appropriate protocol to transmit the data.

The two transport protocols in TCP/IP are the Transmission Control Protocol (TCP) and the User Datagram Protocol (UDP).

## Transmission Control Protocol (TCP)

TCP (Transmission Control Protocol) is a connection-oriented transport layer protocol that provides reliable and error-free delivery of data between devices on a network.

Before sending data, TCP establishes a connection between the sender and receiver using a 3-way handshake. It ensures that all data packets reach the destination correctly and in the proper order.

- Connection-oriented protocol
- Reliable data delivery
- Uses acknowledgments (ACKs)
- Retransmits lost packets
- Performs error checking
- Maintains packet order
- Provides flow control and congestion control

Common Application using TCP:
- HTTP / HTTPs
- FTP
- SMTP
- SSH

### Working of TCP (Transmission Control Protocol)

1. **Connection Establishment (3-Way Handshake)**
    - The sender sends a **SYN** packet.
    - The receiver responds with **SYN-ACK**.
    - The sender replies with **ACK**.
    - A connection is established.
2. **Data Transmission**
    - TCP breaks data into smaller segments.
    - Each segment is assigned a sequence number.
    - The segments are sent to the destination.
3. **Acknowledgment**
    - The receiver sends an ACK (Acknowledgment) for received segments.
    - This confirms successful delivery.
4. **Error Recovery**
    - If a segment is lost or corrupted, TCP retransmits it.
    - This ensures reliable communication.
5. **Connection Termination**
    - After data transfer is complete, both devices exchange FIN and ACK packets.
    - The connection is closed properly.


## User Datagram Protocol (UDP)

UDP (User Datagram Protocol) is a connectionless transport layer protocol that sends data without establishing a connection between the sender and receiver.

Unlike TCP, UDP does not use acknowledgments, error recovery, or retransmission. As a result, it is faster but does not guarantee that data will reach the destination.

- Connectionless protocol
- Fast data transmission
- No handshaking process
- No acknowledgments (ACKs)
- No retransmission of lost packets
- Low overhead
- Does not guarantee delivery or packet order

Common application using UDP:
- DNS (Domain Name System)
- VoIP (Voice over IP)
- Video Streaming
- Online Gaming
- Live Broadcast

### Working of UDP

- The sender creates data packets called **datagrams**.
- UDP adds source and destination port numbers to each datagram.
- The datagrams are sent directly to the destination without establishing a connection.
- The receiver receives the datagrams and passes the data to the appropriate application.
- UDP does not send acknowledgments or check whether the data arrived successfully.
- If a packet is lost, delayed, or arrives out of order, UDP does not retransmit it.

## TCP VS UDP

| TCP (Transmission Control Protocol)          | UDP (User Datagram Protocol)                        |
| -------------------------------------------- | --------------------------------------------------- |
| Connection-oriented protocol                 | Connectionless protocol                             |
| Establishes a connection before sending data | Sends data without establishing a connection        |
| Reliable data delivery                       | Unreliable data delivery                            |
| Uses acknowledgments (ACKs)                  | Does not use acknowledgments                        |
| Retransmits lost packets                     | Does not retransmit lost packets                    |
| Ensures packets arrive in order              | Does not guarantee packet order                     |
| Performs error checking and recovery         | Limited error checking, no recovery                 |
| Slower due to reliability features           | Faster due to low overhead                          |
| Higher overhead                              | Lower overhead                                      |
| Uses 3-way handshake                         | No handshake required                               |
| Suitable for accuracy and reliability        | Suitable for speed and real-time communication      |
| Examples: HTTP, HTTPS, FTP, SMTP, SSH        | Examples: DNS, VoIP, Video Streaming, Online Gaming |

# Internet Layer in TCP/IP Model

The **Internet Layer** is the 3rd layer that is responsible for addressing, routing, and forwarding data packets between different networks. It determines the best path for data to travel from the source to the destination across interconnected networks.

This layer is equivalent to the **Network Layer (Layer 3)** of the OSI model.

- Provides logical addressing (IP addresses)
- Routes data packets between networks
- Determines the best path for data transmission
- Fragments and reassembles packets when necessary
- Handles packet forwarding and delivery

## Protocols of Internet Layer

### 1. Internet Protocol (IP)

**Internet Protocol (IP)** is a protocol used at the **Internet Layer** of the TCP/IP model that provides logical addressing and routing of data packets between networks.

Every device connected to a network is assigned an **IP address**, which helps identify the source and destination of data. IP is responsible for delivering packets from one device to another across different networks.

- Provides logical addressing (IP addresses)
- Identifies source and destination devices
- Routes packets between networks
- Enables communication over the Internet
- Handles packet fragmentation and forwarding

#### Types of IP

| **IPv4**                                                                | **IPv6**                                                            |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Uses a **32-bit address** and supports about **4.3 billion addresses**. | Uses a **128-bit address** and supports a huge number of addresses. |
| Written in **decimal format**. Example: `192.168.1.1`                   | Written in **hexadecimal format**. Example: `2001:db8::1`           |
| Uses **NAT** because IP addresses are limited.                          | Usually does not need NAT because there are plenty of addresses.    |
| Supports **broadcasting** (sending data to all devices on a network).   | Uses **multicast**, which is more efficient than broadcasting.      |
| Uses **ARP** to find MAC addresses.                                     | Uses **NDP** to find MAC addresses and network information.         |
| Security features are added separately.                                 | Has better built-in security support.                               |
| Usually uses **DHCP** or manual configuration for IP assignment.        | Can automatically configure its own IP address using **SLAAC**.     |
| Full form: Internet Protocol Version 4                                  | Full form: Internet Protocol Version 6                              |

### Internet Control Message Protocol (ICMP)

**ICMP (Internet Control Message Protocol)** is a protocol used at the **Internet Layer** of the TCP/IP model to send error messages and network diagnostic information between devices.

ICMP does not transfer user data; instead, it helps devices and routers report problems and check network connectivity.

- Reports network errors
- Tests network connectivity
- Helps troubleshoot network issues
- Provides status and diagnostic messages

#### Working of ICMP

- A device sends an **ICMP Echo Request** message to another device.
- The request travels through the network to the destination.
- The destination device receives the request and processes it.
- The destination sends back an **ICMP Echo Reply** message.
- The sender receives the reply and confirms that the destination is reachable.
- If there is a problem (such as an unreachable destination or expired TTL), ICMP sends an error message back to the sender.


## Address Resolution Protocol (ARP)

**ARP (Address Resolution Protocol)** is a protocol used to find the **MAC address** of a device when its **IP address** is known.

Since devices communicate on a local network using MAC addresses, ARP helps convert an IP address into the corresponding MAC address.

**IP Address tells "Who?"**  
**MAC Address tells "Where exactly?"**

#### Why is ARP Needed?

When a computer wants to send data on a local network, it needs both the **destination IP address** and the **destination MAC address**. Usually, the computer knows the IP address but not the MAC address.

**ARP (Address Resolution Protocol)** solves this problem by finding the MAC address associated with a known IP address, allowing the data to be delivered to the correct device.

### Working of ARP

1. A computer wants to send data to another device and knows its **IP address**.
2. It checks its **ARP cache** to see if the MAC address is already stored.
3. If the MAC address is not found, the computer sends an **ARP Request** to all devices on the network:
    - "Who has this IP address?"
4. The device with that IP address sends back an **ARP Reply** containing its MAC address.
5. The sender stores the MAC address in its ARP cache.
6. The sender then uses that MAC address to send the data to the destination device.

# Application Layer in TCP/IP Model

The **Application Layer** is the top layer of the TCP/IP model and is responsible for providing network services directly to user applications.

It allows software such as web browsers, email clients, and file transfer programs to communicate over a network.

- Provides network services to applications
- Enables communication between users and the network
- Handles web browsing, email, file transfer, and remote access
- Defines how applications exchange data

### Working of Application Layer

1. The user interacts with an application (e.g., a web browser).
2. The application creates a network request.
3. The Application Layer uses the appropriate protocol (HTTP, FTP, SMTP, etc.).
4. The data is passed to the Transport Layer for transmission.
5. At the destination, the Application Layer delivers the data to the correct application.
