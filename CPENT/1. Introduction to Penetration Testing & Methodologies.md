# Penetration Testing

**Penetration Testing (Pentesting)** is the process of **legally trying to exploit a computer system, network, or application** to find security weaknesses **before a real hacker does**.

The organization gives the penetration tester **permission** to perform the attack.

1. **Penetration testing is an authorized security test** to evaluate an organization's security.
2. It checks whether the organization's **network, applications, systems, and users** are protected from **external and internal attacks**.
3. It tests the effectiveness of **security policies, controls, and technologies** (e.g., firewalls, IDS/IPS, MFA).
4. It **simulates real-world cyberattacks** to identify exploitable weaknesses.
5. It identifies **design weaknesses**, **technical flaws**, and **security vulnerabilities**.
6. It determines the **real impact** of successfully exploiting vulnerabilities.
7. It helps organizations **find and fix weaknesses before attackers exploit them**.
8. The findings are documented in a **comprehensive report** with evidence and remediation recommendations.

# Benefits of Conducting Penetration Testing

- Identifies security threats before attackers exploit them.
- Determines the likelihood (probability) of a cyberattack.
- Ensures the organization's security risk remains within an acceptable level.
- Identifies possible attack paths (attack vectors).
- Assesses the potential business impact of a successful attack.
- Helps prevent future cyberattacks by identifying and fixing weaknesses.
- Verifies that security controls are implemented effectively.
- Improves the return on investment (ROI) of security measures.
- Helps achieve compliance with security standards and regulations (e.g., PCI DSS, ISO 27001, HIPAA).
- Prioritizes high-risk vulnerabilities for faster remediation.
- Identifies application-level security issues before deployment.
- Evaluates the effectiveness of network security devices such as firewalls, routers, and web servers.
- Improves the organization's overall security posture.
- Protects sensitive information and critical business assets.
- Provides recommendations to strengthen the organization's security.

# Penetration Testing Service Delivery Models

## 1. In-house Penetration Testing

- The organization has its **own dedicated penetration testing team**.
- The team performs **regular and continuous security testing**.
- Testers have a **good understanding of the organization's systems**.
- Suitable for **large organizations** with ongoing security needs.

## 2. Outsourced Penetration Testing Service

- The organization **hires a third-party security company**.
- Testing is usually done **at a specific point in time** (e.g., annually or before a major release).
- Provides **independent and unbiased security assessment**.
- Suitable for organizations **without an in-house security team**.

## 3. Penetration Testing as a Service (PTaaS)

- A **cloud-based penetration testing service**.
- Combines **manual testing with automated scanning**.
- Supports **continuous or on-demand security testing**.
- Provides **real-time reports and collaboration** through an online platform.
- Suitable for organizations that require **continuous security monitoring**.

## 4. Crowdsourced Penetration Testing

- The organization invites **multiple ethical hackers worldwide** to test its systems.
- Also known as **Bug Bounty** or **Crowd Testing**.
- Different testers use **different attack techniques**, increasing vulnerability coverage.
- Organizations **reward** testers for valid vulnerability reports.
- Suitable for testing **public-facing applications and websites**.

# ROI (Return on Investment) for Penetration Testing

**ROI (Return on Investment):** Measures whether the money spent on penetration testing provides valuable benefits and cost savings.

|**Point**|**Simple Explanation**|
|---|---|
|**1. Identify vulnerabilities**|Penetration testing helps find, understand, and fix security vulnerabilities before attackers exploit them.|
|**2. Saves money**|Fixing vulnerabilities early is much cheaper than recovering from a cyberattack or data breach.|
|**3. Justifies the investment**|ROI shows management that spending money on penetration testing is beneficial for the organization.|
|**4. Measures cost vs benefit**|It compares the cost of penetration testing with the money saved by preventing security incidents.|
|**5. Supports business decisions**|Companies invest in penetration testing when they understand its security and financial benefits.|

```
ROI = (Expected Returns - Cost of Investment)/Cost of Investment
```

- **Expected Returns** → Money saved by preventing cyberattacks, data breaches, fines, and downtime.
- **Cost of Investment** → Money spent on penetration testing.

# Comparison of Security Audit, Vulnerability Assessment, and Penetration Testing

|**Feature**|**Security Audit**|**Vulnerability Assessment (VA)**|**Penetration Testing (PT)**|
|---|---|---|---|
|**Purpose**|Checks whether security policies and procedures are followed.|Identifies security vulnerabilities in systems and applications.|Simulates real attacks to determine whether vulnerabilities can actually be exploited.|
|**Focus**|Compliance and security standards.|Finding vulnerabilities.|Exploiting vulnerabilities to assess their impact.|
|**Method**|Reviews documents, policies, and configurations.|Uses scanners and manual verification.|Uses manual techniques and tools to simulate real-world attacks.|
|**Exploitation**|❌ No exploitation.|❌ Does not exploit vulnerabilities.|✅ Exploits vulnerabilities in a controlled manner.|
|**Output**|Audit report with compliance findings.|List of vulnerabilities with risk levels.|Detailed report with exploited vulnerabilities, impact, proof of concept, and remediation.|
|**Goal**|Ensure the organization follows security best practices.|Discover security weaknesses.|Demonstrate the real-world impact of security weaknesses.|

## Security Audit

A security audit checks whether an organization follows a set of standards security policies, procedures, configurations, and controls

## Vulnerability Assessment

**Vulnerability Assessment** is the process of **identifying, analyzing, and prioritizing security vulnerabilities** in systems, networks, or applications without exploiting them.

## Penetration Testing

**Penetration Testing** is an **authorized simulation of a real cyberattack** to identify and **exploit vulnerabilities** in a controlled manner to determine their real-world impact.

# Types of Penetration Testing Assessment

## 1. Goal-Oriented (Objective-Oriented) Penetration Testing

**Goal-Oriented Penetration Testing** is a type of penetration test where the **objective is defined before testing begins**. The tester's job is to achieve a specific goal using any possible attack path.

**Examples:**

- Gain Domain Admin access.
- Access confidential data.
- Gain access to the internal network.
- Deface a website.
- Cause a Denial of Service (DoS).

## Compliance-Oriented Penetration Testing

**Compliance-Oriented Penetration Testing** is performed to **meet the security requirements of industry standards, regulations, or laws**.

**Examples:**

- PCI-DSS
- ISO 27001
- HIPAA
- GDPR

The main purpose is to verify that the organization complies with the required security standards.

## Red Team-Based Penetration Testing

**Red Team-Based Penetration Testing** is an **adversary simulation** where testers behave like real attackers to evaluate the organization's **overall security**, including people, processes, physical security, networks, and applications.

The goal is to test whether the organization can **detect, respond to, and stop a real attack**.

|**Type**|**Purpose**|**Focus**|**Example**|
|---|---|---|---|
|**Goal-Oriented**|Achieve a specific objective.|Reach a predefined goal.|Gain Domain Admin access or steal sensitive data.|
|**Compliance-Oriented**|Meet security standards and regulations.|Verify compliance with required standards.|PCI-DSS, ISO 27001, HIPAA assessment.|
|**Red Team-Based**|Simulate a real cyberattack.|Test the organization's overall security and response.|Simulate an Advanced Persistent Threat (APT) attack.|

# Strategies of Penetration Testing

## 1. Black Box Testing

**Black Box Penetration Testing** is a testing strategy in which the penetration tester has **no prior knowledge** of the target environment. The tester is only given the target (e.g., a website or IP address) and must gather all information through reconnaissance and enumeration, just like a real external attacker.

## 2. White Box Penetration Testing

**White Box Penetration Testing** is a testing strategy in which the penetration tester has **complete knowledge** of the target environment before testing begins.

The organization provides all necessary information to perform a thorough security assessment.

## 3. Gray Box Penetration Testing

**Gray Box Penetration Testing** is a testing strategy in which the penetration tester has **partial knowledge** of the target environment.

The tester is provided with limited information, such as a normal user account or basic documentation.

This simulates an attacker who has already gained some level of access.

Combination of both **Black Box** and **White Box**

| **Feature**              | **Black Box**              | **White Box**                | **Gray Box**                                       |
| ------------------------ | -------------------------- | ---------------------------- | -------------------------------------------------- |
| **Knowledge of Target**  | No knowledge               | Full knowledge               | Partial knowledge                                  |
| **Simulates**            | External attacker          | Insider/Developer            | Authenticated user or attacker with limited access |
| **Credentials Provided** | No                         | Yes                          | Limited                                            |
| **Testing Time**         | Longest                    | Shortest                     | Moderate                                           |
| **Main Focus**           | Real-world external attack | Complete security assessment | Internal and external security assessment          |

# Common Areas of Penetration Testing

## 1. Network Penetration Testing

**Network Penetration Testing** is the process of testing an organization's **network infrastructure** to identify security weaknesses, misconfigurations, and vulnerabilities that attackers could exploit.

**Common Security Issues**

- Insecure network protocols (e.g., Telnet, FTP)
- Unused open ports and services
- Unpatched operating systems and software
- Misconfigured firewalls, IDS/IPS, routers, and servers

## 2. Web Application Penetration Testing

**Web Application Penetration Testing** is the process of testing a **website or web application** to identify vulnerabilities caused by insecure design, coding, or configuration.

**Common Security Issues**

- SQL Injection
- Cross-Site Scripting (XSS)
- Broken Authentication
- Broken Authorization
- Broken Session Management
- Weak Cryptography
- Improper Error Handling

## 3. Social Engineering Penetration Testing

**Social Engineering Penetration Testing** evaluates how vulnerable **employees** are to manipulation and deception by attackers.

**Common Security Issues**

- Clicking phishing emails
- Sharing sensitive information
- Falling for phone scams (vishing)
- Allowing unauthorized visitors
- Plugging in unknown USB devices

## 4. Wireless Network Penetration Testing

**Wireless Network Penetration Testing** is the process of testing **Wi-Fi networks** for security weaknesses and misconfigurations.

**Common Security Issues**

- Rogue or unauthorized access points
- Weak Wi-Fi encryption (e.g., WEP)
- Weak Wi-Fi passwords
- Outdated wireless technologies

## 5. Mobile Device Penetration Testing

**Mobile Device Penetration Testing** identifies security issues in **mobile devices and mobile applications**.

**Common Security Issues**

- Improper BYOD (Bring Your Own Device) policy
- Unauthorized mobile devices
- Rooted or jailbroken devices
- Weak mobile security settings
- Connecting to insecure public Wi-Fi

## 6. Cloud Penetration Testing

**Cloud Penetration Testing** evaluates the security of **cloud infrastructure, cloud services, and cloud-hosted applications**.

**Common Security Issues**

- Poor access control (IAM)
- Insecure APIs
- Unencrypted data
- Misconfigured cloud storage
- Insider threats
- Weak network security

|**Area**|**What is Tested?**|**Main Goal**|
|---|---|---|
|**Network Penetration Testing**|Networks, servers, routers, firewalls|Find network security weaknesses|
|**Web Application Penetration Testing**|Websites and web applications|Find web vulnerabilities|
|**Social Engineering Penetration Testing**|Employees and security awareness|Test human security weaknesses|
|**Wireless Network Penetration Testing**|Wi-Fi networks and access points|Secure wireless communication|
|**Mobile Device Penetration Testing**|Mobile devices and apps|Protect mobile devices and data|
|**Cloud Penetration Testing**|Cloud infrastructure and services|Secure cloud resources and data|

# Penetration Testing Process

## 1. Defining the Scope

**Defining the Scope** is the planning phase where the organization and the penetration tester decide **what will be tested, how it will be tested, and the rules of engagement**.

**Activities**

- Define the **scope (extent)** of testing.
- Identify the **systems, applications, and networks** to be tested.
- Decide **where the testing will be performed from** (internal, external, or both).
- Decide **who will perform the testing** (in-house team or third party).
- Obtain **written authorization** before testing begins.

## 2. Performing the Penetration Test

**Performing the Penetration Test** is the phase where the tester actively assesses the target environment by finding and safely exploiting security vulnerabilities.

**Activities**

- Gather information about the target (Reconnaissance).
- Scan and enumerate systems and services.
- Identify security vulnerabilities.
- Exploit vulnerabilities (if permitted).
- Test network devices, systems, applications, and configurations.
- Assess the impact of successful attacks.

## 3. Reporting and Delivering Results

**Reporting and Delivering Results** is the final phase where all findings are documented and shared with the organization.

**Activities**

- List all identified vulnerabilities.
- Classify vulnerabilities by severity (**Critical, High, Medium, Low**).
- Provide proof of concept (PoC) and evidence.
- Explain the business and technical impact.
- Recommend remediation steps to fix the vulnerabilities.

# Penetration Testing Phases

## 1. Pre-Attack Phase

**Pre-Attack Phase** is the **planning and information gathering phase**, where the penetration tester collects information about the target before attempting any attack.

**Activities**

- Gather information (Reconnaissance)
- Identify target systems
- Scan the network
- Enumerate services
- Identify possible vulnerabilities
- Plan the attack strategy

Collect as much information as possible before launching the attack.

## 2. Attack Phase

**Attack Phase** is the phase where the penetration tester **tests and exploits identified vulnerabilities** to determine whether they can be successfully compromised.

**Activities**

- Exploit vulnerabilities
- Gain initial access
- Escalate privileges
- Access sensitive data
- Move laterally (if permitted)
- Maintain access (if within scope)
- Validate the impact

Determine whether vulnerabilities can be exploited and assess their impact.

## 3. Post-Attack Phase

**Post-Attack Phase** is the final phase where the tester **documents all findings, assesses the impact, and provides recommendations** to improve security.

**Activities**

- Document vulnerabilities
- Collect screenshots and evidence
- Assign risk levels (Critical, High, Medium, Low)
- Explain business impact
- Recommend remediation
- Prepare the final penetration testing report

Help the organization understand the findings and fix the identified security issues.

# Need for a Methodology

A **Penetration Testing Methodology** is a **step-by-step process** that helps penetration testers perform testing in a **planned, organized, and consistent** manner.

- Helps testers think and attack like real hackers.
- Provides a standardized and structured testing process.
- Produces documented and repeatable test results to verify fixes.
- Ensures consistent testing and reduces errors.
- Helps testers plan an effective attack strategy based on gathered information.
